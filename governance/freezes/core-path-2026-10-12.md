# Freeze of the non-core areas (#1237)

A record, not enforcement (see `README.md`). Nothing here gates a merge.

## Decision

The owner approved the freeze on 2026-10-12 with the message "推进吧" (go ahead) on the audit that proposed it. The proposal is the section "Freeze" of #1237: no new work until the core path is green. The core path is `large_model_value_v0`: capital-adjusted gross profit per employee, three tiers, P/GP gap, selection, the Today page, and the backtest.

## What frozen means

- No new capability, no new file, and no net growth in these areas.
- Allowed: a deletion; a change that the core path needs (name the issue in the PR); a security fix.
- A change that is not allowed waits. The owner can lift the freeze on #1237.

## Measure it again

```sh
git fetch origin main
git log origin/main --since=<date> --numstat --format= -- <paths of one area> \
  | awk '$1 ~ /^[0-9]+$/ {a += $1; d += $2} END {print "+" a, "-" d}'
```

The method finds only the paths above. A change to a frozen area under another path does not show.

## Exit

The owner lifts the freeze on #1237 when the core path has been green in production for two nights in a row. Green means:

- `nightly_backtest_pipeline` and `topt_live_pipeline` succeed in production with definition 1.0.0.
- `uv run python tools/vision_audit.py --env production` shows the gates #56, #29, #30 and #31 as VERIFIED. Gate #54 needs the owner's sign-off by design.

## Why a record and not a gate

ADR A8 says that merge gates enforce technical baselines only, and that observability does the rest. This directory holds records, and the owner removed the enforcing governance machine on 2026-07-17. A gate on line counts would also block a fix from another lane. Each change to a frozen area shows in review. The measurement above is cheap to repeat.
